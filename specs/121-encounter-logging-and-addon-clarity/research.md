# Research: Encounter Logging and Addon Clarity

## Desktop surfaces

Decision: audit centralized strings, data lifecycle view, every history/catalog/details modal, generated history/import/projection and catalog worker diagnostics.
Rationale: centralized copy alone misses engineering jargon in inline and generated status/error branches. Research agents found terminal/flush-bound/evidence wording throughout.
Alternatives: glossary-only or a few tooltips fails #249; new live controls would change behavior unnecessarily.

## Addon command contracts

Decision: retain commands/codes/versions; rewrite all messages in both Lua modules with feature-specific explanation. Preserve chosen/requested/effective mode, current fight and session distinctions.
Rationale: desktop sees disk snapshots, not current recording. Unknown-version evidence cannot be cleared under the current guard; invalid same-version state can. Catalog start replaces prior finished/failed/cancelled data, cancel retains an incomplete snapshot, combat needs explicit resume and reload does not reconstruct collection runtime.
Alternatives: hide unknown facts or introduce desktop control would misrepresent authority. Save/import-before-clear is optional preservation guidance, not an eligibility requirement.

## Package identity and deletion

Decision: preserve ownership and inventory tests, recalculate normalized Catalog.lua self-checksum and use existing exact byte comparison to offer Update Data.
Rationale: no protocol/schema change. Clear encounter, clear catalog, delete desktop history and uninstall affect distinct copies/subtrees.
Alternatives: migration or schema bump adds unnecessary work.
