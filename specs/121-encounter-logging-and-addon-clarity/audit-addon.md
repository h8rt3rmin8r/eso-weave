# S121 addon messaging audit

Scope: every player-facing message in the ESO Weave Data catalog and encounter modules. The tables identify original and final message prefixes; dynamic branches and shared instructions are defined below and retained in the linked source. All 54 original literal message sites were reviewed and rewritten. Two additional help messages complete the save/import/delete flow. Neither addon control logic, stored fields, controller versions, nor capture schemas changed.

In-game commands read current addon state. ESO saves addon data to SavedVariables on /reloadui, logout, or exit. Desktop Last saved recording state describes that file and may lag. Installing the package does not start a new collection or recording; retained explicitly enabled continuous recording may recover after a reload.

## Dynamic wording and retained states

- Catalog status has separate current runtime and retained-result branches. Running/paused displays category progress and record count; retained complete data requires save and catalog-compiler import-collector. Incomplete data cannot be imported or resumed after reload. Starting replaces inactive collection; cancellation retains an unusable incomplete snapshot. Clear touches only catalog addon data and requires a save to persist deletion.
- Encounter status explains selected mode, requested user enablement, effective mode, game environment, current fight presence/identifier, retained session disposition, finished/partial fight counts, interruption count/reason, and failure. Internal mode, state and failure codes remain in parentheses beside explained values for troubleshooting.
- State mappings: stopped means off; waiting means enabled and waiting for combat; capturing means recording the current fight; interrupted means recording interrupted; failed means recording stopped by an error. Single means one fight; continuous means multiple fights until stopped.
- Failure and partial maps explain storage-pressure, callback-failed, clock-reset, terminal-reserve-exhausted, interruption-limit, state-invalid, player-deactivated, runtime-interrupted, capture-overflow, user-stopped, started-mid-combat, unsupported-value, record-limit, byte-limit, and string-limit. Codes remain intact internally. Complete versus partial completion is explicit; partial completion names the controlled reason.
- Shared save instruction uses /reloadui, logout, or exit ESO, then File > Encounter History > Import Saved Capture for the matching environment. Shared preservation instruction makes import optional before clearing, never an enforced or proven prerequisite.
- Clear deletes addon encounter records/session state while off, keeps selected mode/environment, catalog data, and desktop history. Same-version invalid data has explicit discard recovery. Unsupported-version data remains preserved and all commands, including clear, are refused; compatible-version or backup recovery is suggested.
- The additional Catalog help continuation explains progress, resume, cancellation retention, scoped clear, save, maintainer import, and unchanged Encounter History. The additional Encounter help continuation includes shared save/import wording and optional preservation before scoped clear. Source: Catalog.lua command; Encounter.lua command; shared SAVE_AND_IMPORT/PRESERVE_AND_CLEAR.
- Catalog exceptions remain stored in the existing internal failure field but no arbitrary exception or callback value is displayed in chat. Player failure copy gives a controlled game-read/collection-limit explanation and retry command. Encounter reasons are existing controlled codes with presentation explanations.
