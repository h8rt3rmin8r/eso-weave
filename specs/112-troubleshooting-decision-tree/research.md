# Research: Accessible Troubleshooting Decision Tree

## Decision 1: Use a sequential symptom chain

**Decision**: Start at the first failing observation, test the five families in order, route each match to a terminal evidence card, and advance each non-match to the next family. End unmatched symptoms at feature status and Live Log.

**Rationale**: A five-way hub at 400 SVG units requires shared trunks, crossings, crowded labels, or very small cards. A sequential chain preserves top-down reading, gives every edge its own lane, and visually reinforces the prose rule to stop at the first failing observation.

**Alternatives rejected**:

- A flat symptom table repeats what the prose tables already do and hides shared ordering.
- A radial or five-way hub conflicts with the maintained top-down design and deterministic clearance contract.
- Five separate figures would fragment one reader task and multiply drift.

## Decision 2: Keep one 400-unit hand-authored SVG

**Decision**: Use a 400 by 1520 static SVG with the established ink canvas, typography, semantic colors, rounded cards, orthogonal arrows, and stable topology metadata.

**Rationale**: Existing CSS is bounded at 40 rem, which resolves to the 400-pixel mdBook content treatment already verified by four diagrams. Hand-authored SVG keeps text, accessibility metadata, geometry, and source review deterministic without adding a toolchain.

**Alternatives rejected**:

- Raster output loses semantic structure and scales less cleanly.
- Mermaid or another renderer adds runtime or build dependency and weakens byte identity.
- A wider canvas would shrink more at the established content width and make labels harder to read.

## Decision 3: Treat the figure as routing, not diagnosis

**Decision**: Use symptom wording on decision cards and evidence wording on endpoints. Never label an endpoint as a cause or fix.

**Rationale**: Many later symptoms can be caused by an earlier unavailable prerequisite. The canonical prose deliberately stops at the first failing observation, and the visual must not overstate certainty.

## Decision 4: Extend the existing policy record

**Decision**: Add one `DOCUMENTATION_DIAGRAMS` record and one browser `DIAGRAMS` record. Expand finite counts and receipt tests instead of creating an S112-specific manifest.

**Rationale**: The current registry already owns source placement, exact alternatives, text anchors, SVG safety, intrinsic geometry, generated bytes, rendering observations, and layout observations. A parallel manifest would create two authorities for the same asset.

## Decision 5: Preserve the prose byte-for-byte inside the shared flow

**Decision**: Insert the figure before the existing fenced tree, add the `Shared diagnostic flow text equivalent` subheading, and ensure that the adjacent tree explicitly routes every figure branch.

**Rationale**: The pre-implementation assumption that later sibling symptom sections made the shorter fenced tree complete did not survive hosted accessibility review. The adjacent fallback must carry the same five branch decisions as the figure. Its governed code-block digest changes deliberately, while every detailed symptom section remains authoritative and present.

## Decision 6: Record implementation authorities without workflow trigger expansion

**Decision**: Name prose and source authorities plus update triggers in the compatibility record and S112 contract. Do not add Rust paths to the docs workflow filter.

**Rationale**: The authorities explain when maintainers must review the figure, but application-source changes already run the general CI workflow and do not necessarily require a documentation job. Making every named source file trigger the complete docs browser matrix would be disproportionate for a figure that summarizes stable public states. The source policy still runs whenever the figure or documentation changes.

## Verification Consequences

- Source policy must require the exact fifth record and labels.
- Generated policy must require local byte-identical delivery.
- The rendering matrix becomes 5 x 2 x 2 x 2, or 40 cells.
- The layout receipt becomes five unique direct-SVG observations.
- The finite source inventory becomes 11 screenshots or illustrations, 5 diagrams, 5 brand images, and 1 decorative wordmark.
- The shared S088 figure matrix remains 20 representative cells because the new asset reuses the existing diagram interaction class.
