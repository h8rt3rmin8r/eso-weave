# S120 Recovery Contract

## Desktop controls

Filter positively classified gamepad primaries before distinct desktop signature counting. One valid desktop assignment is valid even with controller assignments. Two different desktop assignments remain conflicting. Controller-only is unsupported; empty is unbound. No slot-number assumptions or native binding mutation.

Route the decoded fact through the existing input boundary. Equivalent facts preserve epochs; changed or unavailable facts invalidate queued work. RealSink continues gate/epoch checks and owned-control cleanup.

## Version source and package support

Read no more than eight recent commits per selected channel. Require a valid head SHA and source timestamp; find the newest parseable client version. Read API documentation from that exact head SHA with a bounded response. Reject missing/invalid API, malformed data, future source times, and sources older than 30 days. The 30-day window bounds stale mirrors while allowing ordinary patch cadence; it is source freshness, not a compatibility guarantee.

Unknown source evidence cannot establish supported API. Reviewed package API tokens remain independent of observed/cached numbers. Never add an arbitrary observed number to a package manifest. Managed lifecycle retains its existing ownership and rollback contracts.

Existing addon status/detail text reports package compatibility, client and API identity, unknown source state, and next action without a transient top-of-dashboard row. Startup checks run once per selected application environment and errors do not block UI startup.

## HUD

No transient freshness notification is rendered. Loss/cause/recovery logs contain bounded state facts, not input contents or raw encounter data. Retention expiry logs once. Rendering and input policy retain the S098 contracts apart from the removed UI row.
