# Implementation Plan: Documentation Diagram Legibility

**Branch**: `codex/s103-documentation-diagram-legibility` | **Date**: 2026-09-15 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/103-documentation-diagram-legibility/spec.md`

## Summary

Recompose all four static documentation SVGs on taller canvases with explicit node, edge, stage, and branch-label identities. Extend the existing dependency-free Chrome smoke with direct-SVG element measurements so stage gaps, node clearance, crossings, label association, arrowhead clearance, and all-visible-element containment become deterministic merge gates. Preserve readable expanded width for tall assets through the existing bounded dialog panel.

## Technical Context

**Language/Version**: SVG 1.1-compatible markup, JavaScript on Node.js 24, Markdown

**Primary Dependencies**: Node standard library, mdBook 0.5.4, host-provided Chrome-compatible browser

**Storage**: Checked-in SVG and Markdown, generated mdBook output

**Testing**: Node test runner, documentation policy, direct-SVG browser layout smoke, 32-cell rendering smoke, mdBook test/build, linkcheck, spelling, text hygiene

**Target Platform**: GitHub Pages and bundled loopback documentation on Windows and Linux

**Project Type**: Single-crate desktop application with one shared mdBook source

**Performance Goals**: Reuse the existing browser process and add only four bounded direct-SVG observations

**Constraints**: No package graph, remote renderer, raster golden, runtime diagram library, second viewer, broad interaction redesign, or application behavior change. One narrow intrinsic-size scrolling adjustment is permitted for tall S103 assets.

**Scale/Scope**: Four SVG assets, one browser-smoke module and test module, compatibility record, changelog, build-plan chronology, spec packet

## Phase 0: Research

1. Audit all current node bounds, stage gaps, routing lanes, edge labels, intrinsic geometry, and adjacent prose.
2. Compare pixel-golden, source-only, and direct-SVG element measurement approaches.
3. Define stable clearance thresholds with tolerances that reject overlap without binding tests to rasterization.

Output: [research.md](research.md)

## Phase 1: Design

1. Define node, edge, branch-label, layout-observation, and receipt records.
2. Define taller per-diagram canvases and orthogonal routing rules.
3. Define pure validation failures and four direct-SVG browser observations.

Outputs: [data-model.md](data-model.md), [contracts/diagram-layout.md](contracts/diagram-layout.md), [quickstart.md](quickstart.md)

4. Preserve intrinsic expanded width for tall diagrams through the existing scrollable panel and add a paired no-shrink assertion.
5. Update compatibility evidence, build-plan chronology, and changelog decisions.
