# Implementation Plan: Documentation Diagram Rendering Compatibility

**Branch**: `codex/s086-diagram-rendering-compatibility` | **Date**: 2026-09-11 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/086-diagram-rendering-compatibility/spec.md`

## Summary

Harden the four local documentation SVGs with explicit intrinsic geometry, scope responsive CSS separately for primary and expanded images, prove source-to-generated identity and media type, and add a dependency-free headless-Chrome rendering smoke over the generated manual.

## Technical Context

**Language/Version**: JavaScript on Node.js 24, Markdown, SVG, CSS

**Primary Dependencies**: Node standard library, mdBook 0.5.4, host-provided Chrome-compatible browser

**Storage**: Checked-in SVG and Markdown; generated mdBook output; release-embedded documentation bytes

**Testing**: Node test runner, documentation policy, headless browser smoke, mdBook build/test, linkcheck, spelling, text hygiene, Cargo merge gate

**Target Platform**: GitHub Pages and bundled loopback documentation on supported desktop platforms

**Project Type**: Single-crate desktop application with one shared mdBook documentation source

**Performance Goals**: One browser process and a bounded matrix that completes within the documentation CI job

**Constraints**: No npm graph or browser download; no runtime renderer; no application or addon behavior changes; no #155 interaction redesign

**Scale/Scope**: Four SVG assets, four pages, one CSS surface, one policy module and test module, one browser-smoke module, workflow and governance records

## Phase 0: Research

1. Reproduce the public normal and expanded states in both themes.
2. Audit source SVG geometry, generated mdBook markup, CSS inheritance, delivery media types, and generated byte identity.
3. Compare structural-only, runtime-renderer, and dependency-free browser-smoke options.

Output: [research.md](research.md)

## Phase 1: Design

1. Define exact per-diagram geometry and generated figure contracts.
2. Define a finite surface, theme, viewport, and state matrix.
3. Define semantic browser observations and mutation boundaries.

Outputs: [data-model.md](data-model.md), [contracts/diagram-rendering.md](contracts/diagram-rendering.md), [quickstart.md](quickstart.md)
