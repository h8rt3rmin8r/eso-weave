## Windows observation

- Environment: Microsoft Windows 11 Pro 64-bit, version 10.0.26200, build 26200.
- Browser: Google Chrome 152.0.7977.76.
- Released package: `eso-weave-0.15.0-x86_64-windows.msi`.
- Existing installed version: v0.14.0 in the machine-wide MSI location.
- Tested v0.15.0 payload: the released MSI's administrative image at
  `PFiles/ESO Weave/eso-weave.exe` in the isolated verification directory.

A silent in-place upgrade was attempted and rejected by Windows Installer with
error 1730 because removing the existing machine-wide v0.14.0 installation
requires elevation. The existing installation was left intact. Administrative
extraction of the exact released MSI succeeded without rebuilding or altering
the payload.

From that v0.15.0 payload, the shipped **Help > Documentation** action opened
Chrome at `http://127.0.0.1:8304/eso-weave/`. Socket inspection attributed the
listener to the v0.15.0 application process and showed an IPv4 loopback-only
binding. The rendered page title was `ESO Weave Documentation`.

The release operator then directly inspected the opened documentation and
confirmed that it works. At the operator's instruction, that direct acceptance
closes the presentation verification instead of continuing automated desktop
interaction. No further desktop automation was performed after that direction.

## Linux package observation

- Environment: Ubuntu 24.04 x86_64 under WSLg with a Wayland session.
- Network state: package-manager DNS access was unavailable during the run.
- Installed package: `eso-weave 0.15.0-1` from the released deb.
- Installed executable: `/usr/bin/eso-weave`.
- Portable artifacts: the released AppImage and tarball were inspected directly.

The deb installed and its shipped executable launched while the environment had
no usable package-manager network access. The AppImage and tarball contain the
same release-built application and no documentation sidecar. Platform-neutral
documentation routing, assets, search data, methods, reuse, and shutdown are
covered by the release commit's documentation contract tests and by the green
Linux release job.

The deb inspection also exposed an unrelated package-metadata defect: its
control data omits the Debian `Maintainer` field. The package still installs and
launches, so this does not contradict the bundled-documentation result. The
packaging repair is tracked separately in
<https://github.com/h8rt3rmin8r/eso-weave/issues/105>.
